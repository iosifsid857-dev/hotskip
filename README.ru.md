# HOTskip

Запуск MoE-нейросетей, которые **больше, чем RAM и видеопамять вместе**, на обычном игровом ноутбуке с
пригодной для разговора скоростью. HOTskip — это набор правок для [llama.cpp](https://github.com/ggml-org/llama.cpp)
и небольшая утилита командной строки.

> Статус: исследовательский прототип, проверен на одном ноутбуке. English version: [README.md](README.md).

## Идея

В MoE-модели каждый токен использует лишь несколько «экспертов» на слой (Qwen3.6-35B-A3B: 8 из 256,
gpt-oss-120b: 4 из 128). По трассам видно, что эксперты используются очень неравномерно: 5% самых
популярных делают 28% работы, а 10% не нужны вообще. HOTskip держит каждого эксперта там, где он
дешевле всего:

| Уровень | Что там лежит | Как выбирается |
|---|---|---|
| **Видеопамять** | самые «горячие» эксперты из всех слоёв | по трассам, в пределах бюджета VRAM |
| **RAM** | фиксированное число «ячеек» на слой: часть закреплена за популярными, остальные — LRU | популярность + недавность |
| **SSD** | все остальные, читаются по требованию через `O_DIRECT`, параллельно | — |

Плюс:

* **Холодные эксперты считает процессор прямо там, где они лежат.** На ноутбуке перегнать эксперта в
  видеокарту по PCIe (~12 GB/s) дольше, чем посчитать из RAM (~36 GB/s).
* **Предзагрузка.** Роутер следующего слоя применяется к текущему состоянию и угадывает его экспертов
  (58% промахов угадывается); фоновые потоки начинают их читать заранее.
* **Пропуск слабых экспертов.** Если эксперта нет в RAM и его вес мал — он пропускается, а не читается с
  SSD. Порог подбирается для каждой модели по проверке качества.
* **Групповое чтение длинных сообщений** на видеокарте: каждый эксперт читается с SSD максимум раз на порцию.
* **Без 60-гигабайтных копий:** утилита пишет маленький «скелет», холодные эксперты читаются из исходного файла.

## Результаты (ноутбук: 32 GB RAM, 8 GB VRAM)

| Модель | Файл | Больше памяти в | обычный llama.cpp | **HOTskip** |
|---|---|---|---|---|
| Qwen3.6-35B-A3B Q4_K_M | 21 GB | помещается (занимает ~7 GB RAM) | — | **17–19 ток/с** |
| gpt-oss-120b MXFP4 | 65 GB | 1.6 раза | 1.42 ток/с | **4.9–7 ток/с (×3.5–5)** |
| DeepSeek-V4-Flash (284B) Q2_K | 98 GB | 2.4 раза | 0.49 ток/с | **~3 ток/с (×6)** |

Качество проверено для каждой модели (perplexity, KL-дивергенция с оригиналом): без пропуска HOTskip
считает то же самое, что llama.cpp. Подробности и все сырые замеры — в [README.md](README.md) и `research/`.

## Установка

```
git clone https://github.com/iosifsid857-dev/hotskip && cd hotskip
scripts/build.sh
ln -s "$PWD/hotskip.py" ~/.local/bin/hotskip
```

Нужно: Linux с systemd, видеокарта NVIDIA с CUDA, Python 3 с `numpy`, быстрый NVMe SSD.

## Использование

```
hotskip build модель.gguf --title "Моя модель"   # трассы, подбор уровней под этот компьютер, хранилище
hotskip run <имя>                                 # чат в браузере + OpenAI-совместимый API
hotskip start <имя> / hotskip stop                # фоновый сервер для ярлыков в меню
hotskip tune <имя> skip=0.4 ctx=32768             # настройки модели
```

## Ограничения

* Прототип: проверен на одном ноутбуке и трёх моделях (архитектуры `qwen35moe`, `gpt-oss`, `deepseek4`).
* Пока только NVIDIA/CUDA и только Linux.
* Агенты работают, но на самых больших моделях медленно: там упор в скорость генерации.
